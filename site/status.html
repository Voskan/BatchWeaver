Implemented, in development, and required before stable v1

BatchWeaver is a substantial working compiler/runtime toolkit distributed as a public beta. This page separates verified implementation from experimental or absent integrations and from evidence that cannot be manufactured by documentation alone.

Stable v1.0.0 is not published. The source, tests, release pipeline, and public beta are real; the mandatory stable evidence period, migration matrix, API freeze, and wider compatibility evidence are incomplete.

Working product capabilities

Public typed contracts

Requests, outcomes, providers, operation semantics, policies, configuration, diagnostics, catalogs, and declarations are implemented and documented.

Explicit request-coalescing runtime

Instance-scoped engine, request scopes, partitioning, bounded queues, independent cancellation, deadlines, deduplication, memoization, retries, fallback, result validation, statistics, and hooks.

Static analysis and proof

Package loading, SSA, conservative call graph/effects, declaration discovery, candidates, strategy-specific proof obligations, explicit assumptions, witnesses, deterministic certificates, and fail-closed rejections.

Transformation and overlay execution

Versioned plans, source anchors, static loop prefetch, runtime lowering, generated typed bridges, deterministic diffs, Go overlays, transformed build/test/run, atomic materialization, backup, recovery, and revert.

Adapter and protocol foundation

Adapter SDK, exact-key database/sql PostgreSQL reads, HTTP explicit batching, OpenAPI vendor extensions, Redis mapping/cluster slots, GraphQL parsing and resolver waves, gRPC metadata and correlation policies.

Compatibility and operations

  • Additional Go patch/minor versions
  • go.work, vendor, and offline modes
  • Windows arm64
  • Long production-like workload evidence

Only combinations listed in the compatibility matrix are claimed.

Deliberate limits

Behavior BatchWeaver does not claim

  • It does not prove every Go program or transform every N+1 pattern.
  • It does not infer arbitrary network fusion or backend batch endpoints.
  • It does not batch writes automatically or weaken transaction boundaries.
  • It does not upload source, runtime payloads, credentials, tenant IDs, or raw keys.
  • It does not mutate source merely by scanning, proving, importing packages, or opening an editor.
  • It does not promise batching will improve every workload.
  • It does not provide hosted SLSA attestation or cryptographic release signatures today.
  • It does not declare prerelease APIs stable v1.
